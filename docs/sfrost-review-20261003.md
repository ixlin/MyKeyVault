- 后续维护已完成：生产 Harness 从 `0.1.5-rc.1` 升级至 npm latest `0.2.0-rc.2`。下文“首次尝试”保留事故记录；未选择 alpha `0.2.1-alpha.1`。

- 非登录请求仍要求登录；Markdown 的脚本内容保持转义；凭据状态不返回 Key。回归检查没有创建或删除用户内容。
- MyKeyVault、微信公众号服务没有在此次 sfrost 维护中更新。未提交工作树中已有的 scraper.py 改动。

## Harness 首次尝试未完成的原因

候选包第一次安装可用，但添加解压依赖安全修复后重新安装造成主机严重负载升高，并短时影响网站连接。停止本次安装任务后网站恢复。无已确认的 OOM 日志，不能据此宣称是内存耗尽。

改用受限安装后，观察到进程处于 `mem_cgroup_handle_over_high`，持续触发内存限额回收，依赖没有完整解包。服务器物理内存约 1.6 GiB，升级前可用约 299 MiB。即使短暂停止 Harness，受限安装仍未完成。进一步提高资源限额被安全审查拒绝，未绕过该拒绝。

最终停止安装任务、恢复旧 Harness，认证回归通过。未切换生产版本链接，未迁移生产会话或模型设置。保留候选目录供后续检查，不可直接当作可用运行环境。

后续建议在独立 Linux 构建环境准备并验证依赖，再安排维护窗口切换；或由用户决定是否升级服务器内存。不能直接复制 Mac 的 node_modules，因为存在平台原生依赖。

0.2.x 包含 Messages API、配置导入及会话日志变化。升级必须同时验证旧会话读取、文件上传、模型 Key 管理、实际模型调用和产物发布，失败时恢复包版本与一致状态备份，而不只是回退代码链接。

## 依赖安全检查

网关 npm audit 本次无已知漏洞。后续成功部署的 Harness 使用 fflate 0.8.3 override 修复解压漏洞。另有 http-cache-semantics 的共享缓存告警，检查时没有可用修复版本。所观察 Harness 遥测 HTTP 调用没有启用该缓存配置；这是依赖告警，不是已证实的网站泄露。
