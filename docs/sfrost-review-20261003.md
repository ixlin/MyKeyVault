# sfrost.cn 运维与功能检查（2026-10-03）

## 实际交付和版本边界

- 生产 Harness 保留 `0.1.5-rc.1`，没有声称升级完成。官方 npm latest 为 `0.2.0-rc.2`，alpha 为 `0.2.1-alpha.1`；不选择 alpha。
- 门户网关已升级 Node.js 22.19.0 → 22.23.3、pg 8.23.0 → 8.23.1。Markdown-it 15.0.2 已是本次检查时最新版。
- 修复表单请求类型不正确时返回通用 500 的问题，分别返回 415/413/400；先合并字节再解码，避免中文跨网络分段时损坏。
- 本地及服务器均通过语法检查与 5 项测试。认证回归涵盖工作台、知识库、BLOG、后台、新建文章、附件管理、个人中心、账号设置、模型设置、模型凭据状态、Markdown 预览和 Harness 登录衔接。
- 非登录请求仍要求登录；Markdown 的脚本内容保持转义；凭据状态不返回 Key。回归检查没有创建或删除用户内容。
- MyKeyVault、微信公众号服务没有在此次 sfrost 维护中更新。未提交工作树中已有的 scraper.py 改动。

## Harness 升级未完成的原因

候选包第一次安装可用，但添加解压依赖安全修复后重新安装造成主机严重负载升高，并短时影响网站连接。停止本次安装任务后网站恢复。无已确认的 OOM 日志，不能据此宣称是内存耗尽。

改用受限安装后，观察到进程处于 `mem_cgroup_handle_over_high`，持续触发内存限额回收，依赖没有完整解包。服务器物理内存约 1.6 GiB，升级前可用约 299 MiB。即使短暂停止 Harness，受限安装仍未完成。进一步提高资源限额被安全审查拒绝，未绕过该拒绝。

最终停止安装任务、恢复旧 Harness，认证回归通过。未切换生产版本链接，未迁移生产会话或模型设置。保留候选目录供后续检查，不可直接当作可用运行环境。

后续建议在独立 Linux 构建环境准备并验证依赖，再安排维护窗口切换；或由用户决定是否升级服务器内存。不能直接复制 Mac 的 node_modules，因为存在平台原生依赖。

0.2.x 包含 Messages API、配置导入及会话日志变化。升级必须同时验证旧会话读取、文件上传、模型 Key 管理、实际模型调用和产物发布，失败时恢复包版本与一致状态备份，而不只是回退代码链接。

## 数据和 HTTPS

- 一次性备份在服务器 `/var/backups/sfrost/20261003/`：PostgreSQL 自定义格式备份、网关与私有附件/配置归档、停止 Harness 后的状态归档。目录 0700，文件 0600；秘密不进仓库。
- 未发现 sfrost 数据的完整自动备份方案；现有主机维护主要备份 MyKeyVault。优先新增数据库、附件、Harness 状态的定期备份与恢复演练，并保留异机副本。
- sfrost.cn 证书有效至 2026-11-20，覆盖主域与通配符子域；acme-sh 自动续期定时器工作正常，下次计划续期 2026-10-21。没有为验证而强制消耗证书签发额度。
- 主机 nginx、PostgreSQL 保留现有 Debian 安全维护版本，没有跨大版本升级数据库或影响其他站点。

## 优化清单（建议，不表示已实现）

| 模块 | 建议优先完善 |
| --- | --- |
| 工作台 | 最近文档/文章、继续阅读、快捷写文章/上传；模型状态区分已配置、未配置、服务不可用。目前服务不可用可能被误显示为 Key 未配置。 |
| BLOG | 草稿自动保存、离开提醒、版本历史与回收站；图片粘贴/拖入、已有附件复用；文章搜索、筛选与分页。现有格式工具和图片/附件入口已确认存在。 |
| 知识库 | 分类/标签、标题和正文搜索、Markdown 目录及阅读宽度控制、重复文件检测、导入状态、回收站；保持默认不向量化。Office 预览需评估进程资源，不重复启动重型转换服务。 |
| 后台 | 目前主要是 BLOG 文章管理；统一文章、文档、附件、导入失败、备份与服务状态，增加可审计的操作记录。 |
| 个人中心 | Key 配置与可用性分开呈现、明确连接错误、登录设备管理；若开放多用户，先实施角色权限、独立内容与凭据隔离。当前共享管理员架构不能直接充当多租户系统。 |
| Harness | 先完成受控升级与回归；保留独立上游运行包，不对上游代码做门户定制，避免升级覆盖。 |

需要用户决定：网站继续个人私用还是多用户；BLOG 文章继续登录可见还是公开；Harness 下一步采用独立构建部署，还是先调整服务器规格。未经确认不改变内容公开范围、不购买服务器资源。

## 依赖安全检查

网关 npm audit 本次无已知漏洞。候选 Harness 发现 fflate 解压漏洞可用 0.8.3 修复，但候选未部署，因此不能声称生产已修复。另有 http-cache-semantics 的共享缓存告警，检查时没有可用修复版本。所观察 Harness 遥测 HTTP 调用没有启用该缓存配置；这是依赖告警，不是已证实的网站泄露。
