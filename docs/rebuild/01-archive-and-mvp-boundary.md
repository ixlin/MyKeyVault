# MyKeyVault 重建：归档与 MVP 边界

状态：执行中（仅本地只读盘点；未触碰生产）  
日期：2026-07-17

## 目标

将产品收敛为面向个人用户的 AI 时代私密信息保险库。首个可验收版本在 PC 端跑通：多用户注册、加密保存私密记录、受控 MCP 调用、调用后轮换确认与审计。

## 非破坏性归档策略

旧系统在新系统本地验证前不得删除。生产数据库、上传文件、配置和服务均不做写入。

| 范围 | 当前内容 | 处理 |
| --- | --- | --- |
| Key Vault | `VaultAccounts`、`Tags`、`UserKeys`、Identity、小程序账户页 | 仅作迁移参考；新库重建，不复用现有明文记录模型 |
| 微信图文 | `WechatArticle*`、爬虫服务、PPT/AI 萃取、运行上传文件 | 归档，禁止带入新应用 |
| Tushare | `Tushare*`、财务数据、CLI、JWT API | 归档，禁止带入新应用 |
| 旧小程序 | 旧账户/标签/仪表盘页 | 归档后按新 API 与体验重写 |

实施顺序：

1. 在 Git 创建可追溯的归档点，并输出代码/数据库/运行文件清单。
2. 对生产数据库、配置和运行文件做备份（需 owner 当轮批准）。
3. 新应用使用独立项目、独立数据库、独立配置和独立发布目录。
4. 新 PC 端通过本地验证后再讨论数据迁移与生产切换。

## MVP：做什么

- 独立用户注册、登录、邮箱确认、找回密码和账户锁定/限流。
- 私人 Vault：账号密码、API Key、服务器、数据库、链上账户、自定义记录。
- 标签、搜索、收藏、归档、创建/编辑/删除，全部按用户隔离。
- 敏感字段加密存储，默认掩码展示；查看、复制、MCP 请求、轮换确认均审计。
- 公开 MCP 协议和接入说明；用户创建可撤销、限定范围和有效期的个人访问令牌。
- MCP 只允许读取非敏感元数据、创建“受控使用请求”、确认凭据已轮换；禁止返回任何秘密明文。

## MVP：明确不做

- 团队、共享空间、成员管理、导出。
- 自动登录第三方平台、保存第三方平台主账号密码、RPA 改密。
- 钱包私钥签名、交易、助记词派生或托管。
- 批量明文读取、把密钥写进模型上下文、自动把密钥填入任意网站。

## 后续的安全连接器方向

对模型而言，标准 MCP 的工具输出就是模型上下文，不能安全承载密钥明文。后续要支持“AI 代办而不见密钥”，需另建一个不经过模型文本上下文的受控执行通道：

- 本地连接器：用户设备上的守护进程/浏览器扩展在用户确认后直接向目标进程注入短期凭据。
- 服务器与数据库：优先短期账户、SSH 证书、数据库临时密码或受控代理，而非下发长期 root/管理员密码。
- 第三方平台 RPA：作为高风险可选连接器；每个连接器需要单独授权、隔离存储、最小范围、操作录像/审计和撤销。不得作为首版安全承诺。
